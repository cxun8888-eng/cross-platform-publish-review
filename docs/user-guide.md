# 端到端使用指南

本指南描述一次完整业务操作，而不是开发环境安装。环境尚未准备好时先阅读[从零开始](getting-started.md)。

## 发布前

1. 确认浏览器中已安装并启用 `Publish Review Bridge`；
2. 在扩展弹窗确认应用地址和回调路径正确；
3. 登录目标平台官方账号；
4. 在宿主应用准备游客可见的公开标题、正文和标签；
5. 准备本地图片，但不要把本地文件路径写进草稿 payload；
6. 确认平台账号、库存、预算、档期和合规要求。

## 从宿主应用发起

宿主应用调用 `buildDraftHandoffUrl`，然后让当前标签进入返回的官方 URL。当前公开扩展按 `source=publish-review-demo` 识别草稿。

建议当前标签跳转，而不是新开多个标签。回执会使用同一标签返回，用户能清楚看到“宿主应用 → 官方平台 → 宿主应用”的路径。

## 在官方页面操作

发布桥接助手会显示当前草稿摘要和步骤状态。操作原则：

- 文案可由扩展填充；
- 本地素材始终由用户选择；
- 账号与发布设置由用户检查；
- 验证码、风控和二次确认由用户完成；
- 找不到唯一目标时改为平台原生按钮，不要连续盲点。

“确认并发布”是高风险动作。使用测试账号或不希望提交时，请在该按钮之前停止。

## 发布后的回流

### `resolved`

抖音或小红书检测到可接受的公开作品链接或标题匹配的看板指标后，返回：

```json
{
  "version": 1,
  "platform": "douyin",
  "outcome": "resolved",
  "returnMode": "workspace",
  "completedAt": "2026-09-01T02:00:00.000Z",
  "workUrl": "https://www.douyin.com/video/1234567890123456789",
  "title": "示例标题",
  "metrics": {"views": 1200, "likes": 80}
}
```

`workUrl`、`title` 和 `metrics` 都是可选字段。页面变化、数据延迟或标题无法匹配时，回执可能不完整。

### `triggered`

微博或用户手动返回时，可能只有：

```json
{
  "version": 1,
  "platform": "weibo",
  "outcome": "triggered",
  "returnMode": "workspace",
  "completedAt": "2026-09-01T02:00:00.000Z"
}
```

这只说明扩展触发了平台按钮或返回动作，不能作为发布成功凭证。

## 手动创建作品复盘

自动回执适合衔接体验，手动链接查询适合后续刷新数据：

1. 在平台确认作品已经公开；
2. 复制官方作品链接；
3. 在复盘表单选择平台并粘贴链接；
4. 创建异步任务；
5. Worker 通过 Mock 或 RedFox Provider 获取详情；
6. 后端按 `scope_id + platform + work_id` 更新作品，并追加不可变快照。

同一作品重复查询不会创建重复作品记录，但会为不同采集时间追加快照。比当前最新时间更旧的快照不会覆盖最新指标。

## 结果应该如何解释

- 页面可见指标与供应商指标可能存在延迟；
- `null` 表示上游未提供或值无效，真实的 `0` 会被保留；
- 复盘只描述采集时刻，不构成流量、转化、订单或收入承诺；
- 微博当前没有手动复盘 Provider；
- Mock 数据全部是虚构数据，不能用于业务决策。
